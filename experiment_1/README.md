# Experiment 1 — Does visual grounding decay survive control for prefix redundancy?

Pilot implementation of the marginal/total dependence decomposition from
`docs/research_proposal_prism.pdf` §5.1–§5.2, on a small MathVista sample.
Goal: compute β_M (marginal/controlled-direct slope), β_T (total slope),
and Δβ = β_T − β_M, and see whether reported grounding decay (β_M < 0)
survives once prefix redundancy is controlled for (β_T ≈ 0 vs β_T < 0).

## Pipeline

```
data_loading.py   -> experiment_1/data/mathvista_sample.jsonl + data/images/
inference.py      -> experiment_1/results/per_example/{pid}.json
decomposition.py  -> experiment_1/results/aggregate/{summary.json, per_step_measures.csv, per_example_slopes.csv}
```

```bash
pip install -r requirements.txt -r experiment_1/requirements.txt
python experiment_1/data_loading.py
python experiment_1/inference.py          # slow: 4 forward passes/step + 2 generations/example
python experiment_1/decomposition.py
```

Swap models by editing `model.name` in `config.yaml` (default:
`Qwen/Qwen2-VL-2B-Instruct`, a Colab/Kaggle-friendly pilot size).
`inference.py --limit N` runs only the first N cached examples, useful for
a smoke test before committing to the full ~75-example sample.

## What's implemented, following the proposal's §5.1 table exactly

For each step `s` of a trajectory `y = (y_1,...,y_S)` generated with the
image present, four teacher-forced conditions are scored:

| Condition | Image | Prefix | Log-likelihood |
|---|---|---|---|
| C1 | I (present) | y_<s | ℓ₁ |
| C2 | Ĩ (ablated) | y_<s | ℓ₂ |
| C3 | I (present) | scrub(y_<s) | ℓ₃ |
| C4 | Ĩ (ablated) | scrub(y_<s) | ℓ₄ |

```
M_s = ℓ₁ - ℓ₂           controlled direct effect ("marginal" — what most prior work measures)
T_s = ℓ₁ - ℓ₄           total visual dependence
C_s = T_s - M_s = ℓ₂ - ℓ₄   prefix-carried / indirect dependence
S_s = ℓ₃ - ℓ₄           visual sufficiency
R_s = C_s / max(T_s, ε)     redundancy ratio, clipped to [0,1]
```

`β_M`, `β_T` are slopes of `M_s`, `T_s` on normalised step index `ŝ = s/S`
per proposal §5.2. `Δβ = β_T - β_M`.

## Design decisions made for this pilot (confirmed with the user first)

These are exactly the places the proposal leaves open or flags as risk;
everything below was a deliberate choice, not a silent approximation:

1. **Four-condition harness, not two.** The user's original ask ("run the
   model twice, with/without image") only yields M_s. Computing T_s and
   Δβ requires C3/C4, which need a scrub operator — confirmed with the
   user before implementing.
2. **Scrub operator = blind regeneration** (proposal §5.3's "cleanest
   causally" option): `scrub(y_<s)` is built from a *second* trajectory
   `z = (z_1,...,z_Z)`, generated by the same model from the question
   alone with the image ablated from the start. `scrub(y_<s)` is defined
   as the first `min(s-1, Z)` steps of `z` (`common.py::cumulative_text`,
   `inference.py::scrub_prefix`).
3. **Matched by step index, not token count.** The proposal says "a
   prefix of matched length" without specifying step vs. token matching.
   This pilot matches by step index (`z_<s` for `y_<s`) because it is
   simplest to implement correctly; if `z` is shorter than `s-1` steps,
   the scrub prefix is capped at all of `z`. Revisit if step counts
   between the real and blind trajectories diverge a lot in practice —
   `n_steps` for both trajectories is logged per example so this is
   auditable from `results/per_example/*.json`.
4. **Image ablation = mean-pixel fill**, the first (simplest) of the
   proposal's five listed operators (§5.4). The proposal's headline
   operator, region-blur, needs a question-relevant-region localizer and
   is out of scope for this pilot. Ablation preserves image size, so the
   vision-token count — and therefore prompt structure — is identical
   across image-present/image-ablated conditions.
5. **Step segmentation = sentence-split** on the free-text CoT (proposal
   defines steps abstractly and doesn't specify text segmentation).
   `common.py::segment_steps`.
6. **Aggregation = per-example OLS slope, then mean + percentile
   bootstrap CI across examples** (`decomposition.py`), not the
   proposal's full mixed-effects model with random intercepts by item
   *and* model (§5.2) — this pilot only runs one model, and a single
   random-effects axis adds a `statsmodels` dependency for little benefit
   at ~75 examples. A pooled (unclustered) OLS slope is also reported as
   a fast secondary check. Upgrade to `statsmodels.MixedLM` when scaling
   to the multi-model sweep in Phase 2 of the proposal.
7. **Sample = 75 items from MathVista `testmini`** (config default),
   matching the proposal's Phase 0 sanity-anchor dataset and its own
   ~50-100 pilot-scale sample size.

## Explicitly out of scope for this pilot

Everything below is real proposal content but belongs to later phases,
not the "does decay survive prefix control" pilot question:
- Scrub-fidelity human audit / Gate G1 (§5.3)
- The necessity × sufficiency taxonomy and confabulation rate (§5.5)
- The policy-independent demand estimator `d_s` and PRISM-Minimal (§5.6–5.7)
- Multi-model, multi-benchmark sweep and mixed-effects regression (Phase 2)
- Region-blur ablation and the other 4 ablation/4 scrub operator cross-grid

## Output files

- `results/per_example/{pid}.json` — real & blind trajectories, per-step
  ℓ₁..ℓ₄.
- `results/aggregate/per_step_measures.csv` — every step's M_s, T_s, C_s,
  S_s, R_s, s_hat.
- `results/aggregate/per_example_slopes.csv` — per-example β_M, β_T, Δβ,
  mean R_s.
- `results/aggregate/summary.json` — aggregate β_M/β_T/Δβ with bootstrap
  CIs, pooled-OLS secondary check, mean redundancy ratio, and a mechanical
  read of the proposal's §5.2 three-way outcome split (real / artifactual
  / regime-dependent) — treat as a pointer to inspect, not a conclusion.
